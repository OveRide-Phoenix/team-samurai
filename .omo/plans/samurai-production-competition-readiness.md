### Binding runtime and evidence decisions (Metis corrections)
These decisions are part of tasks 1–8, not optional design alternatives.

1. **Queueable parent:** register a plain `SamuraiParentAgent` subclass produced by `create_parent_agent`, retaining the existing ID. Override its supported `deep_copy(update=...)` method to reconstruct fresh model wrappers and all four tool closures through that constructor, sharing only settings/DB connections. The installed queue resolver calls this method per execution; stock Agno deep_copy deliberately shares models and is insufficient here. Registry instances are marked non-executable; a pre-hook raises InputCheckError before tools/provider work if the queue falls back to a registry instance after copy failure. Apply validated update fields with existing copy semantics. Remove `_install_factory_run_read_compat` and its now-unused factory route patch after plain-agent run reads pass. Resolve user/session/run IDs from authenticated native run arguments, never a captured HTTP request or client dependency. References: installed agno/os/job_queue.py:2462-2498; agno/agent/_utils.py:112-133; app.py:59-106,262-263; parent.py:1056-1077.
2. **Immutable work scope:** introduce `backend/src/samurai/execution_state.py` and a small `samurai_work_intents` PostgreSQL table in the existing DB schema. Fields: logical work UUID, parent run/session ID, owner ID, child session/company ID, operation, stage, expected revision, normalized approved-input JSON, SHA-256 fingerprint, active/terminal state and accepted artifact IDs. This is an approval/idempotency ledger, never a second company-state store. Native queue rows remain scheduling authority; canonical artifacts remain in the child Agno session. Journey stage enum is exactly brief/research/strategy/plan; operation enum maps existing bounded tools (journey, launch drafts, metrics analysis, read-only state). Persist founder stage ceiling on enqueue through validated server input; default new free-form journey input authorizes brief only. More advanced console requests must supply the same validated stage selection or receive a clarification without side effects. No model-generated stage constitutes new approval. On first tool invocation, transactionally bind normalized arguments/fingerprint before child execution; retries use the persisted arguments directly, not freshly invented tool arguments. Conflicting tool/stage/revision selection is rejected before child/provider work. Read-only conversation can complete without a write intent. Existing launch/metrics actions need explicit operation input and retain their existing authorization gates.
3. **Admission and transactions:** use a narrowly scoped `SamuraiPostgresDb` subclass in execution_state.py, preserving native PostgresDb interfaces. Its queue enqueue transaction atomically creates/reuses the work intent and native job, with a partial unique active-work index on `(owner_id, company_id)` (initial intake uses the stable parent session ID until company binding exists). Same idempotency key plus identical fingerprint returns the same ticket; a changed payload returns 409; distinct pending company work returns 409, not a second job. No new global execution scheduler: max_concurrency=2 is explicitly per replica, normal maximum two replicas yields four slots, rolling deployments may temporarily exceed four. This is a soft spending control, not a hard fleet concurrency guarantee. Queue depth 10 is the native global pending limit. Shared Redis is for events/cancellation only, not canonical state.
4. **Accepted-state fence:** carry `get_worker_ownership(parent_run_id)` worker_id and attempt from agno.run.concurrency into trusted child context. At each acceptance, one PostgreSQL transaction locks the native job row, work-intent row and child `agno_sessions` row in that order; checks current locked_by/attempt, running/noncancelled status, authenticated owner, approval fingerprint and expected revision; then updates `session_data.session_state.company` and accepted IDs/binding in the ledger atomically. Native queue table name must be obtained from the configured PostgresDb, not guessed. A duplicate accepted intent returns its retained artifact. Compare revision in SQL, not only Python. Override/delegate affected upsert_session persistence so an old Agno in-memory session cannot overwrite protected company or parent-binding fields afterward; preserve unrelated session fields and run writes. Parent binding is rehydrated from the committed work-intent record on retry/read, including death between child commit and parent save. Cancellation persistence and acceptance contend on the same job-row lock; once cancellation commits, later acceptance is forbidden. Do not hold a DB transaction across a Gemini call. All company, launch and analysis acceptance paths use this fence.
5. **Worker availability:** cost-estimate artifact contains exact deployment settings consumed by execution: instance-based CPU allocation, minimum 1/maximum 2 backend instances, native values recorded in task 1, Redis prefix `samurai:production:v1` (separate local/test prefixes), deployment_id `samurai-production-v1` stable across compatible revisions. queue timeout = seven configured model timeouts plus 60 seconds for parent/DB cleanup, explicitly set uniformly.
